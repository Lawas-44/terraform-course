Temario / Módulo 02

Tu primer proyecto: el flujo de trabajo

init → plan → apply → destroy, sin gastar un céntimo, usando providers locales.

Nivel: BásicoDuración: 1,5 hTest: 6 preguntasRetos: 2Proyecto: paso 3

Objetivos

Al terminar este módulo sabrás:

  • Crear un proyecto mínimo y entender qué archivos genera Terraform.
  • Ejecutar el flujo completo init, plan, apply y destroy.
  • Leer e interpretar la salida de un plan (+, ~, -, -/+).
  • Entender qué es el archivo de estado y para qué sirve.

Lección

Un proyecto es una carpeta

Un proyecto de Terraform es una carpeta con archivos que terminan en .tf. Terraform lee todos los .tf de la carpeta en la que estás.

Para practicar sin gastar dinero usaremos dos providers que funcionan en tu ordenador, sin nube:

  • random: inventa valores al azar (nombres, números, contraseñas).
  • local: crea archivos en tu ordenador.

Qué significa cada parte:

  • terraform { ... }: indica qué providers necesitamos y qué versión.
  • resource "random_pet" "nombre": pide un nombre de mascota al azar (por ejemplo, gentle-turtle). random_pet es el tipo y nombre es el nombre que le damos nosotros.
  • resource "local_file" "saludo": crea el archivo saludo.txt. Dentro usa el nombre de la mascota con ${random_pet.nombre.id}.
  • output: muestra un valor en la terminal al terminar.

Paso 2: terraform plan

plan te enseña lo que Terraform va a hacer, pero no hace nada todavía. Léelo siempre antes de aplicar:

Los símbolos del plan:

SímboloSignificado
+Se va a crear
~Se va a modificar
-Se va a borrar
-/+Se va a borrar y crear de nuevo
(known after apply)El valor se conocerá al crearlo

El archivo de estado

Después del apply aparece el archivo terraform.tfstate. Ahí Terraform apunta lo que ha creado. Así sabe, la próxima vez, qué existe ya.

ImportanteNo edites ni borres este archivo. Lo veremos con calma en el módulo 9.

Práctica guiada

Hola, Terraform (carpeta labs/02-primer-proyecto)

  1. Copia el main.tf de ejemplo en una carpeta nueva.
  2. Ejecuta terraform init y explora la carpeta .terraform/.
  3. Ejecuta terraform plan y lee cada línea del plan.
  4. Ejecuta terraform apply y abre saludo.txt.
  5. Cambia length = 3, vuelve a planificar y observa el reemplazo (-/+).
  6. Borra a mano saludo.txt y ejecuta terraform plan: Terraform detecta la diferencia.
  7. Termina con terraform destroy.

Comandos clave

ComandoQué haceCopiar
terraform initInicializa el directorio: descarga providers y módulos.
terraform planMuestra qué cambios se harían sin aplicarlos.
terraform applyAplica los cambios (pide confirmación).
terraform destroyDestruye todo lo gestionado por esta configuración.
terraform outputMuestra los outputs.

Errores frecuentes

Error: Inconsistent dependency lock file
Has cambiado versiones de providers. Ejecuta terraform init -upgrade.
Ejecutar comandos fuera de la carpeta del proyecto
Terraform trabaja sobre el directorio actual (pwd). Usa cd o -chdir=ruta.

Test

Elige una respuesta en cada pregunta. Verás la explicación al momento. Con un 80 % o más, el módulo está superado.

01¿Qué hace terraform init?

init prepara el directorio: backend, providers y módulos. Nunca toca la infraestructura.

02En un plan, ¿qué indica el símbolo -/+?

Es un reemplazo: algún argumento marcado como forces replacement ha cambiado.

03Ejecutas terraform apply dos veces seguidas sin tocar el código. ¿Qué pasa la segunda vez?

Terraform es idempotente: si el estado y la realidad coinciden con el código, no hay nada que hacer.

04¿Cómo sabe Terraform que debe crear random_pet antes que local_file?

Las referencias crean dependencias implícitas; el orden en el archivo no importa.

05¿Qué archivo usa Terraform para recordar qué recursos ha creado?

El estado mapea cada recurso del código con el objeto real que existe.

06¿Qué significa (known after apply)?

Valores como IDs o IPs los genera el proveedor al crear el recurso.

Responde todas las preguntas para ver tu nota.
