Módulo 06

Recursos, data sources y dependencias

Construir una pequeña red y un servidor en AWS entendiendo el grafo de dependencias.

Básico⏱ 2,5 h
En esta página ObjetivosContenidoEjemploPrácticaComandosErrores frecuentesAutoevaluación

🎯 Objetivos de aprendizaje

Al terminar este módulo serás capaz de:

  • Referenciar atributos de un recurso desde otro.
  • Distinguir resource (crea) de data (lee).
  • Entender el grafo de dependencias y el paralelismo.
  • Desplegar una EC2 con un servidor web accesible.

📚 Contenido

  1. Anatomía de un recurso: argumentos de entrada vs atributos calculados («known after apply»).
  2. Dependencias implícitas (por referencia) y explícitas (depends_on).
  3. El grafo: terraform graph y ejecución en paralelo (-parallelism).
  4. Data sources: buscar la AMI más reciente, la VPC por defecto, la cuenta actual, zonas de disponibilidad.
  5. Recursos básicos de red en AWS: VPC, subnet, internet gateway, route table, security group.
  6. user_data para arrancar un servidor web.
  7. Recursos que se reemplazan vs se actualizan («forces replacement»).
✍️ Lección en desarrollo. Este es el guion del módulo. Ve sustituyendo este aviso por la explicación completa de cada punto.

🧩 Ejemplo

🛠 Práctica guiada: Servidor web en EC2

  1. Despliega el ejemplo en la VPC por defecto y abre la URL del output.
  2. Genera el grafo con terraform graph | dot -Tsvg > grafo.svg y analízalo.
  3. Cambia user_data y observa en el plan si actualiza o reemplaza.
  4. Reto: crea tu propia VPC con una subnet pública e internet gateway.
  5. Destruye todo al terminar.
💸 Recuerda: si has creado recursos en la nube, ejecuta terraform destroy al terminar.

⌨️ Comandos clave

ComandoQué haceCopiar
terraform graph | dot -Tsvg > grafo.svgDibuja el grafo de dependencias (requiere Graphviz).
terraform apply -parallelism=5Limita las operaciones simultáneas.
terraform state listLista los recursos gestionados.
terraform state show aws_instance.webMuestra todos los atributos de un recurso.

⚠️ Errores frecuentes

La web no carga
Revisa reglas del security group, IP pública y espera a que termine user_data.
depends_on en todas partes
Úsalo solo si no hay referencia directa; las referencias ya crean la dependencia.
