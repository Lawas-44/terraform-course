Módulo 06

Recursos, data sources y dependencias

Construir una pequeña red y un servidor en AWS entendiendo el grafo de dependencias.

Nivel: BásicoDuración: 2,5 hTest: 6 preguntasRetos: 2Proyecto: paso 7

Objetivos

Al terminar este módulo sabrás:

  • Referenciar atributos de un recurso desde otro.
  • Distinguir resource (crea) de data (lee).
  • Entender el grafo de dependencias y el paralelismo.
  • Desplegar una EC2 con un servidor web accesible.

Lección

Lo que escribes y lo que recibes

Cada recurso tiene dos clases de datos:

  • Argumentos: lo que tú escribes. Por ejemplo, el tamaño del servidor: instance_type = "t3.micro".
  • Atributos: lo que AWS te devuelve al crearlo. Por ejemplo, su IP pública: public_ip.

Por eso en el plan algunos valores aparecen como (known after apply): AWS los decide al crear el recurso.

NotaEn este módulo creamos un servidor pequeño (t3.micro), gratis en la capa gratuita de AWS. Bórralo siempre al terminar.

Consultar cosas que ya existen: data

Un bloque data no crea nada: solo busca información. Por ejemplo, la imagen de sistema operativo más reciente para un servidor:

Se usa con el prefijo data.: data.aws_ami.amazon_linux.id.

¿Por qué no escribir el código de la imagen directamente? Porque cambia según la región y cada pocas semanas sale una versión nueva. Así siempre usas la correcta.

El orden lo decide Terraform

Cuando un recurso usa datos de otro, Terraform sabe que debe crearlo después. Con eso calcula el orden y crea a la vez lo que no depende entre sí.

Al borrar, el orden es el contrario: primero el servidor y después el firewall.

Si hay una dependencia que Terraform no puede ver (porque no hay ninguna referencia), puedes indicarla con depends_on. Úsalo solo cuando sea necesario:

Práctica: un servidor web

Vamos a crear un servidor con una página web. Necesitamos tres cosas: la imagen del sistema, un firewall (en AWS se llama security group) y el servidor (en AWS, instancia EC2).

ConsejoEl servidor tarda uno o dos minutos en instalar la web. Si al principio no carga, espera un poco.

Modificar o recrear

Cambia algo y mira el plan antes de aplicar. Algunos cambios se hacen sobre el mismo recurso (~) y otros obligan a borrarlo y crearlo de nuevo (-/+):

Práctica guiada

Servidor web en EC2

  1. Despliega el ejemplo en la VPC por defecto y abre la URL del output.
  2. Genera el grafo con terraform graph | dot -Tsvg > grafo.svg y analízalo.
  3. Cambia user_data y observa en el plan si actualiza o reemplaza.
  4. Reto: crea tu propia VPC con una subnet pública e internet gateway.
  5. Destruye todo al terminar.
ImportanteSi has creado recursos en la nube, ejecuta terraform destroy al terminar para no pagar por ellos.

Errores frecuentes

La web no carga
Revisa reglas del security group, IP pública y espera a que termine user_data.
depends_on en todas partes
Úsalo solo si no hay referencia directa; las referencias ya crean la dependencia.

Test

Elige una respuesta en cada pregunta. Verás la explicación al momento. Con un 80 % o más, el módulo está superado.

01¿Qué diferencia hay entre resource y data?

Los data sources consultan; nunca crean, modifican ni destruyen nada.

02¿Cómo se referencia el ID de data "aws_ami" "linux"?

Los data sources llevan el prefijo data..

03¿Cuándo necesitas depends_on?

Las referencias ya crean dependencias implícitas; depends_on es para las ocultas.

04El security group y la AMI no se referencian entre sí. ¿Cómo los procesa Terraform?

Los nodos independientes del grafo se ejecutan en paralelo (hasta -parallelism, 10 por defecto).

05¿Por qué usar un data source para la AMI en lugar de escribir su ID?

El data source busca la imagen adecuada en cada región y momento.

06En el plan ves ~ instance_type = "t3.micro" -> "t3.small". ¿Qué pasará?

~ es update in-place: AWS cambia el tamaño parando y arrancando la misma instancia.

Responde todas las preguntas para ver tu nota.
