Qué son los meta-argumentos

Además de sus argumentos propios, cualquier bloque resource acepta cinco argumentos especiales que cambian cómo lo trata Terraform:

Meta-argumentoPara qué sirve
countCrear N copias numeradas
for_eachCrear una copia por cada elemento de un map o set
depends_onDependencias explícitas (módulo 6)
providerElegir un provider con alias (módulo 5)
lifecycleCambiar cómo se crea, actualiza o destruye

Para practicar sin coste, usaremos local_file en los ejemplos. Todo funciona igual con recursos de AWS.

count: N copias

  • count.index vale 0, 1, 2…
  • El recurso pasa a ser una lista: local_file.nota[0], local_file.nota[1]…
  • local_file.nota[*].filename (splat) devuelve una lista con el atributo de todas las copias.

⚠️ Cuidado. Las claves de for_each deben conocerse en el plan. No puedes usar como clave un atributo que se calcula al crear otro recurso (como un ID). Si lo haces verás el error Invalid for_each argument.

lifecycle: controlar el ciclo de vida

El bloque lifecycle acepta varias opciones:

OpciónCuándo usarla
prevent_destroyBases de datos, buckets con datos, zonas DNS: lo que no debe borrarse nunca por error
ignore_changesAtributos que modifica otro sistema (autoescalado, etiquetas que pone otro equipo)
create_before_destroyEvitar cortes de servicio al reemplazar (certificados, instancias tras un balanceador)
replace_triggered_byForzar reemplazo cuando cambia algo relacionado
ℹ️ Nota. Para destruir un recurso con prevent_destroy, primero tienes que quitar esa línea del código. Es intencionado: obliga a pensarlo dos veces y deja constancia en Git.

🛠 Práctica guiada: count vs for_each

  1. Crea 3 archivos locales con count a partir de una lista.
  2. Elimina el elemento del medio y observa el plan.
  3. Repite con for_each y compara.
  4. Añade prevent_destroy a un recurso e intenta destruirlo.
💸 Recuerda: si has creado recursos en la nube, ejecuta terraform destroy al terminar.

⌨️ Comandos clave

ComandoQué haceCopiar
terraform apply -replace="aws_instance.web"Fuerza la recreación de un recurso.
terraform state list 'aws_iam_user.equipo'Lista las instancias de un recurso con for_each.
terraform plan -target='aws_iam_user.equipo["ana"]'Planifica solo un recurso (uso excepcional).

⚠️ Errores frecuentes

The "for_each" value depends on resource attributes that cannot be determined until apply
Las claves de for_each deben conocerse en el plan; usa valores estáticos o variables.
Abusar de -target
Es para emergencias; deja el estado desalineado con el código si se usa como rutina.
