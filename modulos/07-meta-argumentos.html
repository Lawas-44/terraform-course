Módulo 07

Meta-argumentos: count, for_each y lifecycle

Crear múltiples recursos y controlar su ciclo de vida.

Nivel: IntermedioDuración: 2 hTest: 7 preguntasRetos: 2

Objetivos

Al terminar este módulo sabrás:

  • Crear N recursos con count y con for_each, y elegir entre ellos.
  • Controlar el ciclo de vida con lifecycle.
  • Proteger recursos críticos contra borrados accidentales.

Lección

Qué son los meta-argumentos

Son opciones especiales que puedes poner en cualquier recurso para cambiar cómo lo trata Terraform:

OpciónPara qué sirve
countCrear varias copias numeradas
for_eachCrear una copia por cada elemento de una lista de nombres
lifecycleProteger un recurso o cambiar cómo se reemplaza
depends_onIndicar un orden a mano (módulo 6)
providerElegir otra región o cuenta (módulo 5)

En los ejemplos usamos archivos locales para practicar gratis. Con recursos de AWS funciona igual.

count: varias copias

Crea nota-0.txt, nota-1.txt y nota-2.txt. count.index es el número de cada copia, empezando por 0.

Por qué for_each suele ser mejor

Imagina que creas los perfiles con count sobre la lista ["ana", "luis", "marta"] y luego quitas a luis. Con count las copias se identifican por posición: marta pasa de la posición 2 a la 1, y Terraform cree que ha cambiado:

Con for_each solo se borra lo que has quitado:

ConsejoRegla sencilla: usa count para «N copias iguales» o «crear sí/no», y for_each para listas de cosas con nombre.

lifecycle: proteger y controlar

OpciónQué hace
prevent_destroyDa error si algo intenta borrar el recurso. Ideal para bases de datos
ignore_changesTerraform no toca esos datos aunque alguien los cambie fuera
create_before_destroyAl reemplazar, crea el nuevo antes de borrar el viejo

Para poder borrarlo, primero tienes que quitar prevent_destroy del código.

Práctica guiada

count vs for_each

  1. Crea 3 archivos locales con count a partir de una lista.
  2. Elimina el elemento del medio y observa el plan.
  3. Repite con for_each y compara.
  4. Añade prevent_destroy a un recurso e intenta destruirlo.
ImportanteSi has creado recursos en la nube, ejecuta terraform destroy al terminar para no pagar por ellos.

Comandos clave

ComandoQué haceCopiar
terraform apply -replace="aws_instance.web"Fuerza la recreación de un recurso.
terraform state list 'aws_iam_user.equipo'Lista las instancias de un recurso con for_each.
terraform plan -target='aws_iam_user.equipo["ana"]'Planifica solo un recurso (uso excepcional).

Errores frecuentes

The "for_each" value depends on resource attributes that cannot be determined until apply
Las claves de for_each deben conocerse en el plan; usa valores estáticos o variables.
Abusar de -target
Es para emergencias; deja el estado desalineado con el código si se usa como rutina.

01¿Qué valor tiene count.index en la tercera copia de un recurso?

Los índices empiezan en 0: 0, 1, 2.

02¿Cómo creas un recurso solo si var.activar es true?

Es el patrón clásico: 1 copia o ninguna.

03Usas count sobre una lista de 5 nombres y eliminas el segundo. ¿Qué pasa?

Los índices se desplazan y Terraform cree que los recursos 1-3 han cambiado.

04Con for_each = { web = 80, api = 8080 }, ¿qué vale each.value en la copia "api"?

each.key es la clave ("api") y each.value su valor (8080).

05¿Qué opción de lifecycle evita borrar un recurso por accidente?

Hace que cualquier plan que implique destruirlo falle.

06Un equipo modifica las etiquetas de una instancia desde la consola y no quieres que Terraform las revierta. ¿Qué usas?

ignore_changes hace que Terraform no proponga cambios en esos atributos.

07¿Cuál es la alternativa moderna a terraform taint?

-replace fuerza la recreación y muestra el plan antes.
