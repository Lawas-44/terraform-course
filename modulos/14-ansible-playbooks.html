Temario / Módulo 14

Playbooks

Escribir playbooks en YAML para instalar programas, copiar archivos y arrancar servicios.

Nivel: BásicoDuración: 2 hTest: 6 preguntasRetos: 2Proyecto: paso 14

Objetivos

Al terminar este módulo sabrás:

  • Leer y escribir archivos YAML sin errores.
  • Crear un playbook con varias tareas.
  • Usar los módulos más comunes: apt, copy, file, service y user.
  • Entender por qué Ansible es idempotente y probar cambios con --check.

Lección

YAML en cinco minutos

Los playbooks se escriben en YAML, un formato de texto muy sencillo. Solo hay tres reglas importantes:

  1. La sangría (los espacios al principio) indica qué va dentro de qué. Usa siempre espacios, nunca tabuladores.
  2. clave: valor define un dato.
  3. Un guion - al principio indica un elemento de una lista.
ConsejoLos archivos YAML suelen empezar con ---. No es obligatorio, pero es la costumbre.

Qué es un playbook

Un playbook es un archivo con una lista de tareas que Ansible ejecuta en orden en un grupo de servidores. Es como una receta: primero esto, luego esto otro.

  • name: una descripción. Es lo que verás en pantalla.
  • hosts: en qué grupo del inventario se ejecuta.
  • become: true: ejecutar como administrador.
  • tasks: la lista de tareas. Cada tarea usa un módulo (apt, service...) con sus opciones.
Notaansible.builtin.apt es el nombre completo del módulo apt. Se recomienda escribir el nombre completo para evitar confusiones.

Ejecutar un playbook

ResultadoSignificado
okYa estaba bien; no ha hecho falta cambiar nada
changedHa hecho un cambio
failedHa fallado
unreachableNo ha podido conectarse al servidor

Idempotencia: ejecutarlo varias veces

Ejecuta el mismo playbook otra vez:

changed=0: nginx ya estaba instalado y arrancado, así que no ha hecho nada. Como Terraform, Ansible describe cómo debe quedar el servidor y solo cambia lo necesario. Por eso puedes ejecutar un playbook tantas veces como quieras sin miedo.

Probar antes de cambiar

Igual que terraform plan, Ansible puede enseñarte lo que haría sin cambiar nada:

  • --check: simula; no cambia nada.
  • --diff: muestra las líneas que cambiarían en los archivos.

Y para comprobar que el YAML está bien escrito:

Los módulos más usados

MóduloPara qué sirveEjemplo
aptInstalar o quitar paquetes (Ubuntu/Debian)name: nginx, state: present
serviceArrancar, parar o reiniciar serviciosname: nginx, state: started
copyCopiar un archivo o escribir un textosrc: web.css, dest: /var/www/web.css
fileCrear carpetas, enlaces o borrar archivospath: /var/www, state: directory

ImportanteEvita command y shell siempre que exista un módulo para lo que quieres hacer. Los módulos saben si algo ya está hecho; un comando suelto se ejecuta siempre.

Práctica guiada

Mi primer playbook (carpeta labs/14-ansible-playbooks)

  1. Lee el playbook playbook.yml del lab y localiza cada tarea.
  2. Ejecútalo con --check --diff para ver qué haría.
  3. Ejecútalo de verdad y luego otra vez: la segunda vez debe salir changed=0.
  4. Añade una tarea que cree un archivo con copy y vuelve a ejecutarlo.
ImportanteSi has creado recursos en la nube, ejecuta terraform destroy al terminar para no pagar por ellos.

Errores frecuentes

Syntax Error while loading YAML
En YAML la sangría importa: usa siempre espacios (nunca tabuladores) y alinea bien los guiones.
Missing sudo password o Permission denied
La tarea necesita permisos de administrador. Añade become: true al playbook.
Usar command o shell para todo
Busca primero un módulo específico (apt, copy, service...). Los módulos son idempotentes; los comandos sueltos no.
