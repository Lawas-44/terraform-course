Por qué parametrizar

Hasta ahora todos los valores estaban escritos «a fuego» en el código. Pero en la vida real quieres reutilizar la misma configuración con datos distintos: un entorno dev pequeño y barato y un prod grande, una región u otra, un nombre de proyecto u otro. Para eso existen tres herramientas:

HerramientaAnalogíaSintaxis
variableLos parámetros de una funciónvar.nombre
outputEl valor de retornooutput "x" { value = ... }
localsVariables internas de la funciónlocal.nombre

Cómo dar valores a las variables

Hay cinco formas. De menor a mayor prioridad (la última gana):

PrioridadOrigenEjemplo
1 (menor)Valor default de la variabledefault = "dev"
2Variables de entorno TF_VAR_nombreexport TF_VAR_entorno=staging
3Archivo terraform.tfvars (y terraform.tfvars.json)se carga automáticamente
4Archivos *.auto.tfvars (en orden alfabético)comun.auto.tfvars
5 (mayor)-var y -var-file en la línea de comandos (en el orden escrito)-var-file=prod.tfvars
💡 Consejo. Patrón habitual: valores comunes en terraform.tfvars y un archivo por entorno (dev.tfvars, prod.tfvars) que se pasa con -var-file.

Locals: no te repitas

Cuando una misma expresión aparece varias veces, extráela a un local. Son valores internos, calculados, que no se pueden cambiar desde fuera:

Usa una variable si…Usa un local si…

cambia entre entornoses igual siempre pero se repite
debe documentarse como parámetroes un detalle interno

Valores sensibles

Marca como sensitive las variables y outputs con secretos para que Terraform no los muestre por pantalla:

⚠️ Cuidado. sensitive solo oculta el valor en la salida. Sigue guardado en texto plano en terraform.tfstate. Para protegerlo de verdad hay que proteger el estado (módulo 10) y usar gestores de secretos (módulo 13). Y pasa los secretos por TF_VAR_..., nunca en un .tfvars subido a Git.

🛠 Práctica guiada: Parametriza el proyecto del módulo 2

  1. Convierte el nombre del archivo y el contenido en variables.
  2. Crea dev.tfvars y prod.tfvars y aplica con -var-file.
  3. Prueba a dar un valor no permitido y observa la validación.
  4. Exporta TF_VAR_proyecto=demo y comprueba la precedencia.
  5. Saca un output en JSON y fíltralo con jq.

⌨️ Comandos clave

ComandoQué haceCopiar
terraform plan -var="entorno=prod"Asigna una variable desde la línea de comandos.
terraform apply -var-file="prod.tfvars"Carga variables desde un archivo.
export TF_VAR_proyecto=demoAsigna una variable vía entorno (bash).
$env:TF_VAR_proyecto = "demo"Lo mismo en PowerShell.
terraform output -json | jqOutputs en JSON formateado.
terraform output -raw prefijoValor sin comillas, ideal para scripts.

⚠️ Errores frecuentes

Terraform pregunta por una variable cada vez
No tiene default ni valor asignado. Añádelo a terraform.tfvars.
Creer que sensitive cifra el valor
Solo lo oculta en la salida. Protege el estado (backend cifrado, acceso restringido).
