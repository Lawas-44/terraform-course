La terminal sin miedo

Terraform se usa desde la terminal (también llamada consola, shell o línea de comandos). Si nunca la has usado, estos son los conceptos mínimos:

  • Linux y macOS usan Bash o Zsh. Abre la app «Terminal».
  • Windows: usa PowerShell (viene instalado) o, mejor aún, instala WSL (Windows Subsystem for Linux) para tener una terminal Linux real: wsl --install.
  • Siempre estás «dentro» de una carpeta (el directorio de trabajo). Terraform trabaja sobre la carpeta en la que estás.
💡 Consejo. Pulsa Tab para autocompletar nombres de archivos y comandos, y las flechas ↑ ↓ para recuperar comandos anteriores. Te ahorrarán miles de pulsaciones.

Gestionar varias versiones con tfenv

En proyectos reales cada repositorio puede exigir una versión distinta de Terraform. Herramientas como tfenv (o tenv, que también soporta OpenTofu) permiten tener varias instaladas y cambiar entre ellas.

ℹ️ Nota. Para este curso basta con cualquier versión 1.10 o superior. Si ya instalaste Terraform con el gestor de paquetes, no necesitas tfenv todavía.

Cuenta de AWS segura (necesaria desde el módulo 5)

Los módulos 0 a 4 no necesitan nube. Para el resto usaremos AWS. Prepárala bien desde el principio:

  1. Crea la cuenta en aws.amazon.com. El email y contraseña con los que te registras son el usuario root: el más poderoso.
  2. Activa MFA en el usuario root (IAM → Security credentials) y guárdalo. No vuelvas a usar root para el día a día.
  3. Crea un usuario de trabajo. Lo recomendable es IAM Identity Center (inicio de sesión con SSO y credenciales temporales). Alternativa sencilla para aprender: un usuario IAM con la política AdministratorAccess, MFA y access keys.
  4. Crea un presupuesto en Billing → Budgets: «Monthly cost budget» de 5 USD con alerta por email al 80 %.

🛠 Práctica guiada: Entorno listo

  1. Instala Terraform y comprueba la versión con terraform version.
  2. Activa el autocompletado: terraform -install-autocomplete.
  3. Instala la AWS CLI y ejecuta aws configure (o aws configure sso).
  4. Verifica la identidad con aws sts get-caller-identity.
  5. Crea un presupuesto de 5 USD con alerta por email en AWS Budgets.
  6. Crea un repositorio terraform-labs con el .gitignore anterior.

⚠️ Errores frecuentes

terraform: command not found
El binario no está en el PATH. Reabre la terminal o añade la carpeta al PATH.
Usar la cuenta root de AWS con access keys
Nunca. Crea un usuario/rol con permisos y activa MFA en root.
Subir terraform.tfstate o claves a GitHub
Configura el .gitignore antes del primer commit y usa git status antes de cada git add.

1¿Qué comando muestra la carpeta en la que estás trabajando en Bash?

pwd = print working directory.

2¿Cuál de estos archivos SÍ debe subirse a Git?

El lock file fija las versiones exactas de los providers para todo el equipo; el resto contiene binarios o datos sensibles.

3¿Por qué no se sube el archivo terraform.tfstate a un repositorio?

El estado guarda atributos de los recursos, incluidas contraseñas o claves generadas.

4¿Qué comando te dice con qué cuenta y usuario de AWS estás autenticado?

STS (Security Token Service) devuelve la cuenta, el usuario/rol y su ARN.

5¿Qué deberías hacer con el usuario root de AWS?

Root tiene poder ilimitado. Se protege con MFA y se trabaja con usuarios o roles con permisos acotados.
