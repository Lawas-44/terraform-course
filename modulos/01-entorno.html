Módulo 01

Preparación del entorno

Terminal, Terraform, Ansible, claves SSH, editor, Git y una cuenta de AWS preparada de forma segura.

Nivel: BásicoDuración: 1,5 hTest: 6 preguntasRetos: 2Proyecto: paso 2

Objetivos

Al terminar este módulo sabrás:

  • Moverse con soltura por la terminal (Linux/macOS y PowerShell).
  • Instalar Terraform y Ansible.
  • Crear una clave SSH para entrar en los servidores.
  • Configurar VS Code con la extensión oficial de HashiCorp.
  • Preparar Git y un repositorio para los ejercicios.
  • Crear una cuenta en AWS con un usuario no-root, MFA y alertas de presupuesto.

Lección

La terminal

Terraform se usa escribiendo comandos en la terminal (también llamada consola). Es una ventana donde escribes órdenes en lugar de hacer clic.

  • macOS y Linux: abre la aplicación «Terminal».
  • Windows: abre PowerShell. Si quieres una terminal igual que la de Linux, instala WSL con wsl --install.

Siempre estás «dentro» de una carpeta. Terraform trabaja con los archivos de la carpeta en la que estás. Estos comandos te bastan para empezar:

ComandoQué hace
pwdMuestra en qué carpeta estás
lsLista los archivos de la carpeta
mkdir nombreCrea una carpeta
cd nombreEntra en una carpeta
cd ..Vuelve a la carpeta anterior
ConsejoPulsa Tab para autocompletar nombres y la flecha hacia arriba para repetir el último comando.

El editor de código

Te recomendamos Visual Studio Code (gratuito) con la extensión HashiCorp Terraform. La extensión colorea el código, te sugiere palabras mientras escribes y ordena el código al guardar.

  1. Descarga VS Code de code.visualstudio.com.
  2. Abre la sección de extensiones (Ctrl+Shift+X).
  3. Busca «HashiCorp Terraform» e instálala.

Git y qué archivos no subir nunca

Guardaremos el código en Git. Antes de nada, dile a Git quién eres:

Terraform crea algunos archivos que no deben subirse a GitHub porque pesan mucho o tienen datos secretos. Para evitarlo, crea un archivo .gitignore en tu carpeta con este contenido:

Archivo¿Se sube a Git?Motivo
*.tfSíEs tu código
.terraform.lock.hclSíGuarda las versiones exactas de los providers
.terraform/NoSon programas descargados; se pueden volver a descargar
*.tfstateNoPuede contener contraseñas
ImportanteAntes de subir cambios, ejecuta git status y mira la lista de archivos. Si ves un .tfstate, no lo subas.

Cuenta de AWS (a partir del módulo 5)

Los módulos 0 a 4 no necesitan nube. Para los siguientes usaremos AWS. Configúrala con cuidado:

  1. Crea la cuenta en aws.amazon.com. El email con el que te registras es el usuario principal (llamado root).
  2. Activa la verificación en dos pasos (MFA) en ese usuario.
  3. Crea un usuario para trabajar a diario. No uses root para el día a día.
  4. Crea una alerta de gasto en Billing → Budgets, por ejemplo de 5 dólares. Así AWS te avisará si gastas dinero.

ImportanteNunca escribas tus claves de AWS dentro de los archivos .tf. Terraform las lee solas de la configuración que acabas de crear.

Tu clave SSH

Para entrar en los servidores (tú y Ansible) se usa SSH con una clave: un par de archivos. La clave pública se pone en los servidores; la clave privada se queda en tu ordenador y nunca se comparte.

  • id_ed25519: clave privada. No la compartas nunca.
  • id_ed25519.pub: clave pública. Terraform la subirá a AWS.
ImportanteSi ya tenías una clave en ~/.ssh/id_ed25519, no la sobrescribas: pulsa Enter con cuidado o usa la que ya tienes.

Práctica guiada

Entorno listo

  1. Instala Terraform y comprueba la versión con terraform version.
  2. Activa el autocompletado: terraform -install-autocomplete.
  3. Instala la AWS CLI y ejecuta aws configure (o aws configure sso).
  4. Verifica la identidad con aws sts get-caller-identity.
  5. Crea un presupuesto de 5 USD con alerta por email en AWS Budgets.
  6. Crea un repositorio terraform-labs con el .gitignore anterior.

Comandos clave

ComandoQué haceCopiar
terraform versionMuestra la versión de Terraform y de los providers.
terraform -install-autocompleteInstala el autocompletado en bash/zsh.
aws sts get-caller-identityComprueba con qué cuenta y usuario estás autenticado.
tfenv install 1.9.8 && tfenv use 1.9.8Instala y activa una versión concreta (ejemplo).

Errores frecuentes

terraform: command not found
El binario no está en el PATH. Reabre la terminal o añade la carpeta al PATH.
Usar la cuenta root de AWS con access keys
Nunca. Crea un usuario/rol con permisos y activa MFA en root.
Subir terraform.tfstate o claves a GitHub
Configura el .gitignore antes del primer commit y usa git status antes de cada git add.

Test

Elige una respuesta en cada pregunta. Verás la explicación al momento. Con un 80 % o más, el módulo está superado.

01¿Qué comando muestra la carpeta en la que estás trabajando en Bash?

pwd = print working directory.

02¿Cuál de estos archivos SÍ debe subirse a Git?

El lock file fija las versiones exactas de los providers para todo el equipo; el resto contiene binarios o datos sensibles.

03¿Por qué no se sube el archivo terraform.tfstate a un repositorio?

El estado guarda atributos de los recursos, incluidas contraseñas o claves generadas.

04¿Qué comando te dice con qué cuenta y usuario de AWS estás autenticado?

STS (Security Token Service) devuelve la cuenta, el usuario/rol y su ARN.

05¿Qué deberías hacer con el usuario root de AWS?

Root tiene poder ilimitado. Se protege con MFA y se trabaja con usuarios o roles con permisos acotados.

06¿Para qué sirve tfenv?

Permite instalar varias versiones y elegir cuál usar en cada proyecto con .terraform-version.

Responde todas las preguntas para ver tu nota.
