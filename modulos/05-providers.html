Temario / Módulo 05

Providers y conexión con la nube

Configurar el provider de AWS, versiones, lock file, alias y autenticación segura.

Nivel: BásicoDuración: 1,5 hTest: 6 preguntasRetos: 2Proyecto: paso 6

Objetivos

Al terminar este módulo sabrás:

  • Configurar el provider de AWS y autenticarse sin escribir claves en el código.
  • Entender restricciones de versión (=, >=, ~>) y el lock file.
  • Usar varios providers y alias (por ejemplo, dos regiones).
  • Crear el primer recurso real en la nube (un bucket S3).

Lección

Qué es un provider

Terraform por sí solo no sabe crear nada en AWS, Azure o GitHub. Para eso usa providers: complementos que saben hablar con cada servicio. Hay miles en el Terraform Registry (registry.terraform.io).

En la página de cada provider está la documentación de todos sus recursos, con ejemplos. Es la página que más vas a consultar.

Indicar el provider y su versión

Se declara dentro del bloque terraform:

La versión se puede indicar de varias formas:

EscribesAcepta
= 6.2.0Solo la 6.2.0
>= 6.0La 6.0 o cualquiera más nueva
~> 6.0Cualquier 6.x, pero no la 7.0
ConsejoUsa ~>. Recibes mejoras pero evitas versiones nuevas que puedan romper tu código.

El archivo .terraform.lock.hcl

Al hacer terraform init, Terraform elige una versión exacta y la apunta en .terraform.lock.hcl. Así todo el equipo usa la misma versión. Este archivo sí se sube a Git.

Las claves de acceso

Terraform necesita tus credenciales de AWS. Nunca las escribas en el código. Terraform las busca solo en el mismo sitio que la herramienta aws (lo configuraste en el módulo 1):

ImportanteSi subes unas claves de AWS a GitHub, en pocos minutos alguien puede usarlas para gastar dinero en tu cuenta.

Tu primer recurso en la nube: un bucket S3

S3 es el almacenamiento de archivos de AWS. Un bucket es como una carpeta. Crear uno vacío es gratis.

  • Los nombres de bucket deben ser únicos en todo el mundo. Con bucket_prefix, AWS añade un final al azar para que no se repita.
  • force_destroy = true permite borrar el bucket aunque tenga archivos (solo para practicar).
  • aws_s3_object sube un archivo al bucket.

Busca el bucket en la web de AWS (sección S3). Cuando termines, bórralo con terraform destroy.

Práctica guiada

Tu primer bucket S3

  1. Configura un perfil con aws configure --profile curso-terraform.
  2. Crea el bucket del ejemplo y localízalo en la consola de AWS.
  3. Revisa el contenido de .terraform.lock.hcl.
  4. Cambia la restricción de versión y prueba terraform init -upgrade.
  5. Destruye el bucket.
ImportanteSi has creado recursos en la nube, ejecuta terraform destroy al terminar para no pagar por ellos.

Comandos clave

ComandoQué haceCopiar
terraform providersLista los providers que requiere la configuración.
terraform init -upgradeActualiza providers dentro de las restricciones.

Errores frecuentes

No valid credential sources found
No hay credenciales. Revisa AWS_PROFILE y aws sts get-caller-identity.
BucketAlreadyExists
Los nombres de bucket son globales. Usa bucket_prefix o un sufijo aleatorio.

Elige una respuesta en cada pregunta. Verás la explicación al momento. Con un 80 % o más, el módulo está superado.

01¿Qué versiones acepta la restricción ~> 6.0?

~> permite que aumente solo el último número indicado (el menor, en este caso).

02¿Para qué sirve .terraform.lock.hcl?

Garantiza que todos instalan exactamente la misma versión. Se sube a Git.

03¿Cuál es la forma CORRECTA de dar credenciales de AWS a Terraform?

Las credenciales deben vivir fuera del código: perfiles, SSO, variables de entorno o roles.

04Has cambiado version = "~> 5.0" por "~> 6.0". terraform init falla. ¿Qué haces?

El lock file aún apunta a la 5.x; -upgrade permite elegir una versión nueva.

05¿Por qué usamos bucket_prefix en lugar de bucket?

AWS genera un sufijo único para que no choque con buckets de otras personas.

06¿Cómo indicas que un recurso use el provider con alias = "virginia"?

El meta-argumento provider recibe NOMBRE.ALIAS sin comillas.

Responde todas las preguntas para ver tu nota.
