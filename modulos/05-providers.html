Módulo 05

Providers y conexión con la nube

Configurar el provider de AWS, versiones, lock file, alias y autenticación segura.

Básico⏱ 1,5 h
En esta página ObjetivosContenidoEjemploPrácticaComandosErrores frecuentesAutoevaluación

🎯 Objetivos de aprendizaje

Al terminar este módulo serás capaz de:

  • Configurar el provider de AWS y autenticarse sin escribir claves en el código.
  • Entender restricciones de versión (=, >=, ~>) y el lock file.
  • Usar varios providers y alias (por ejemplo, dos regiones).
  • Crear el primer recurso real en la nube (un bucket S3).

📚 Contenido

  1. Qué es un provider: plugin que traduce HCL a llamadas API. Tiers: official, partner, community.
  2. Leer la documentación del Registry: argumentos, atributos exportados, import.
  3. Version constraints y .terraform.lock.hcl; terraform init -upgrade.
  4. Autenticación AWS: cadena de credenciales (variables de entorno, perfiles, SSO, roles). Nunca claves en .tf.
  5. default_tags para etiquetar todos los recursos.
  6. Alias de providers: multi-región y multi-cuenta.
  7. Otros providers útiles para practicar: docker, github, kubernetes, azurerm, google.
✍️ Lección en desarrollo. Este es el guion del módulo. Ve sustituyendo este aviso por la explicación completa de cada punto.

🧩 Ejemplo

🛠 Práctica guiada: Tu primer bucket S3

  1. Configura un perfil con aws configure --profile curso-terraform.
  2. Crea el bucket del ejemplo y localízalo en la consola de AWS.
  3. Revisa el contenido de .terraform.lock.hcl.
  4. Cambia la restricción de versión y prueba terraform init -upgrade.
  5. Destruye el bucket.
💸 Recuerda: si has creado recursos en la nube, ejecuta terraform destroy al terminar.

⌨️ Comandos clave

ComandoQué haceCopiar
terraform providersLista los providers que requiere la configuración.
terraform init -upgradeActualiza providers dentro de las restricciones.
terraform providers lock -platform=linux_amd64 -platform=darwin_arm64 -platform=windows_amd64Añade hashes para varios sistemas al lock file.
export AWS_PROFILE=curso-terraformSelecciona el perfil de AWS (bash).

⚠️ Errores frecuentes

No valid credential sources found
No hay credenciales. Revisa AWS_PROFILE y aws sts get-caller-identity.
BucketAlreadyExists
Los nombres de bucket son globales. Usa bucket_prefix o un sufijo aleatorio.
