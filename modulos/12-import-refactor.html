Módulo 12

Importar y refactorizar

Traer infraestructura existente a Terraform y reorganizar el código sin destruir nada.

Nivel: IntermedioDuración: 1,5 hTest: 6 preguntasRetos: 2

Objetivos

Al terminar este módulo sabrás:

  • Importar recursos creados a mano con el bloque import.
  • Generar código automáticamente con -generate-config-out.
  • Renombrar y mover recursos con moved y dejar de gestionarlos con removed.

Lección

Recursos creados a mano

Es muy habitual encontrarse recursos que alguien creó a mano en la web de AWS. No hace falta borrarlos y crearlos de nuevo con Terraform: se pueden importar. Importar significa decirle a Terraform: «este recurso que ya existe corresponde a este bloque de mi código».

Práctica guiada

Rescata un recurso hecho a mano

  1. Crea un bucket y un security group desde la consola web.
  2. Escribe los bloques import y ejecuta terraform plan -generate-config-out=generado.tf.
  3. Limpia el código generado y aplica hasta que el plan diga «No changes».
  4. Mueve el recurso a un módulo usando un bloque moved.
ImportanteSi has creado recursos en la nube, ejecuta terraform destroy al terminar para no pagar por ellos.

Errores frecuentes

El plan quiere modificar el recurso importado
Tu código no coincide con la realidad. Ajusta argumentos hasta que no haya cambios.
ID de importación incorrecto
Cada recurso usa un formato distinto: consulta la sección «Import» en la doc del provider.

Test

Elige una respuesta en cada pregunta. Verás la explicación al momento. Con un 80 % o más, el módulo está superado.

01¿Qué hace importar un recurso?

El recurso no se modifica; Terraform empieza a gestionarlo.

02¿Dónde encuentras el formato del id para importar un recurso?

Cada tipo de recurso usa un identificador distinto.

03¿Qué comando genera código HCL para los bloques import que aún no tienen resource?

Genera los bloques resource a partir de lo que existe.

04Tras importar, el plan muestra ~ tags = { ... }. ¿Qué significa?

Ajusta el código hasta que el plan no tenga cambios (salvo los intencionados).

05Renombras aws_instance.a a aws_instance.b. ¿Qué bloque evita recrear la instancia?

moved { from = aws_instance.a to = aws_instance.b }.

06¿Qué hace removed { from = X lifecycle { destroy = false } }?

Equivale de forma declarativa a terraform state rm.

Responde todas las preguntas para ver tu nota.
