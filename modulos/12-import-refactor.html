El escenario: infraestructura creada a mano

Es lo más habitual al llegar a una empresa: hay recursos creados desde la consola hace años y quieren pasarlos a Terraform. No hace falta destruirlos y recrearlos: se pueden importar, es decir, decirle a Terraform «este recurso que ya existe corresponde a este bloque de mi código».

El código generado funciona pero es «feo». Límpialo antes de aplicar:

  • Sustituye valores fijos por referencias (vpc_id = data.aws_vpc.default.id).
  • Muévelo al archivo que le corresponda (main.tf, network.tf…).

Repite terraform plan hasta que diga solo importaciones, sin cambios:

⚠️ Cuidado. Si el plan muestra cambios (~) en un recurso importado, significa que tu código no coincide con la realidad y al aplicar modificarías el recurso. Ajusta el código hasta que no haya diferencias, salvo que el cambio sea intencionado.

Refactorizar con moved

Refactorizar es reorganizar el código sin cambiar lo que hace. En Terraform el peligro es que cambiar la dirección de un recurso (renombrarlo o meterlo en un módulo) hace que Terraform lo destruya y lo cree de nuevo. El bloque moved lo evita:

Estrategia para migrar una cuenta entera

  1. Haz inventario: lista los recursos (AWS Resource Explorer, aws resourcegroupstaggingapi get-resources, la factura).
  2. Agrupa por dominios (red, datos, aplicaciones) y empieza por lo que menos cambia (la red).
  3. Escribe bloques import y genera el código con -generate-config-out.
  4. Limpia, introduce variables y módulos, y repite plan hasta *0 to change*.
  5. Aplica y protege los recursos críticos con prevent_destroy.
  6. A partir de ahí, prohíbe los cambios manuales (permisos de solo lectura en la consola) para evitar drift.
ℹ️ Nota. Existen herramientas como Terraformer o former2 que generan código de cuentas enteras. Útiles como punto de partida, pero el código resultante requiere mucha limpieza; el bloque import nativo suele ser mejor opción hoy.

🛠 Práctica guiada: Rescata un recurso hecho a mano

  1. Crea un bucket y un security group desde la consola web.
  2. Escribe los bloques import y ejecuta terraform plan -generate-config-out=generado.tf.
  3. Limpia el código generado y aplica hasta que el plan diga «No changes».
  4. Mueve el recurso a un módulo usando un bloque moved.
💸 Recuerda: si has creado recursos en la nube, ejecuta terraform destroy al terminar.
