Lección

El problema del estado en tu ordenador

Hasta ahora el estado estaba en tu ordenador. Si trabajas con más personas, eso da problemas:

  • Tus compañeros no tienen tu archivo, así que su Terraform no sabe lo que has creado.
  • Si dos personas aplican cambios a la vez, el estado se puede estropear.
  • Si se rompe tu ordenador, pierdes el estado.

La solución es guardar el estado en un sitio compartido. A ese sitio se le llama backend. En AWS lo normal es usar un bucket de S3.

Paso 2: decirle a Terraform dónde guardar el estado

En tu proyecto, añade un bloque backend dentro de terraform:

  • key: la ruta del archivo dentro del bucket. Usa una distinta para cada proyecto.
  • encrypt: guarda el estado cifrado.
  • use_lockfile: activa el bloqueo (lo vemos abajo). Necesita Terraform 1.10 o superior.
ImportanteDentro del bloque backend no se pueden usar variables (var.algo). Si necesitas valores distintos (por ejemplo, uno por entorno), se pasan al ejecutar terraform init -backend-config=archivo.

HCP Terraform

HCP Terraform es un servicio de HashiCorp (la empresa de Terraform) que guarda el estado por ti y además ejecuta los comandos en sus servidores. Tiene un plan gratuito. Para conectarte se usa terraform login.

Práctica guiada

Estado remoto

  1. Crea (con Terraform, en una carpeta bootstrap/) un bucket con versionado y cifrado.
  2. Añade el bloque backend "s3" a tu proyecto y ejecuta terraform init -migrate-state.
  3. Abre dos terminales y lanza apply a la vez para ver el bloqueo.
  4. Crea los workspaces dev y prod y usa terraform.workspace en un nombre.
ImportanteSi has creado recursos en la nube, ejecuta terraform destroy al terminar para no pagar por ellos.

Comandos clave

ComandoQué haceCopiar
terraform init -migrate-stateMueve el estado al nuevo backend.
terraform init -reconfigureReinicializa el backend ignorando la configuración anterior.
terraform init -backend-config=dev.s3.tfbackendConfiguración parcial del backend desde archivo.
terraform force-unlock LOCK_IDLibera un bloqueo atascado (¡asegúrate de que nadie está aplicando!).
terraform workspace listLista workspaces.
terraform workspace new devCrea un workspace.
terraform workspace select prodCambia de workspace.
terraform workspace showMuestra el workspace actual.
terraform loginInicia sesión en HCP Terraform.

Errores frecuentes

Error acquiring the state lock
Alguien (o un proceso caído) tiene el bloqueo. Espera o usa force-unlock con cuidado.
Usar variables dentro del bloque backend
No se permite. Usa -backend-config o archivos .tfbackend.

Test

Elige una respuesta en cada pregunta. Verás la explicación al momento. Con un 80 % o más, el módulo está superado.

01¿Qué problema resuelve el bloqueo (locking) del estado?

Solo una operación puede escribir el estado a la vez.

02Con Terraform 1.10+, ¿cómo se activa el bloqueo en el backend S3?

use_lockfile usa un archivo .tflock en el propio bucket. DynamoDB es el método antiguo.

03¿Por qué el bucket del estado debe tener versionado?

El versionado es tu copia de seguridad del estado.

04Has añadido un bloque backend a un proyecto con estado local. ¿Qué comando ejecutas?

Copia el estado local al nuevo backend.

05¿Puedes usar var.region dentro del bloque backend?

El backend se configura antes de evaluar variables.

06¿Qué devuelve terraform.workspace?

Útil para nombrar recursos o elegir tamaños según el workspace.

07Un apply en CI se cortó y el estado quedó bloqueado. Nadie más está aplicando. ¿Qué haces?

Libera el bloqueo usando el ID que aparece en el mensaje de error.

Responde todas las preguntas para ver tu nota.
