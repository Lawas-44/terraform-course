Módulo 10

Backends remotos, bloqueo y workspaces

Guardar el estado en S3 o HCP Terraform, bloquearlo y gestionar varios entornos.

Intermedio⏱ 2 h
En esta página ObjetivosContenidoEjemploPrácticaComandosErrores frecuentesAutoevaluación

🎯 Objetivos de aprendizaje

Al terminar este módulo serás capaz de:

  • Configurar un backend remoto en S3 con cifrado, versionado y bloqueo.
  • Migrar un estado local a remoto.
  • Comparar workspaces vs carpetas por entorno.
  • Leer outputs de otra configuración con terraform_remote_state.

📚 Contenido

  1. Backends: local, s3, azurerm, gcs, remote/cloud (HCP Terraform).
  2. Backend S3: bucket con versionado y cifrado; bloqueo nativo con use_lockfile = true (Terraform 1.10+). La tabla DynamoDB es el método antiguo, hoy obsoleto.
  3. El problema huevo-gallina: crear el bucket del estado (bootstrap).
  4. terraform init -migrate-state y -reconfigure. Configuración parcial con -backend-config.
  5. Bloqueos atascados: terraform force-unlock.
  6. Workspaces CLI (terraform.workspace) vs un directorio por entorno: ventajas e inconvenientes.
  7. HCP Terraform (antes Terraform Cloud): estado remoto, ejecuciones remotas, variables, plan gratuito.
✍️ Lección en desarrollo. Este es el guion del módulo. Ve sustituyendo este aviso por la explicación completa de cada punto.

🧩 Ejemplo

🛠 Práctica guiada: Estado remoto

  1. Crea (con Terraform, en una carpeta bootstrap/) un bucket con versionado y cifrado.
  2. Añade el bloque backend "s3" a tu proyecto y ejecuta terraform init -migrate-state.
  3. Abre dos terminales y lanza apply a la vez para ver el bloqueo.
  4. Crea los workspaces dev y prod y usa terraform.workspace en un nombre.
💸 Recuerda: si has creado recursos en la nube, ejecuta terraform destroy al terminar.

⌨️ Comandos clave

ComandoQué haceCopiar
terraform init -migrate-stateMueve el estado al nuevo backend.
terraform init -reconfigureReinicializa el backend ignorando la configuración anterior.
terraform init -backend-config=dev.s3.tfbackendConfiguración parcial del backend desde archivo.
terraform force-unlock LOCK_IDLibera un bloqueo atascado (¡asegúrate de que nadie está aplicando!).
terraform workspace listLista workspaces.
terraform workspace new devCrea un workspace.
terraform workspace select prodCambia de workspace.
terraform workspace showMuestra el workspace actual.
terraform loginInicia sesión en HCP Terraform.

⚠️ Errores frecuentes

Error acquiring the state lock
Alguien (o un proceso caído) tiene el bloqueo. Espera o usa force-unlock con cuidado.
Usar variables dentro del bloque backend
No se permite. Usa -backend-config o archivos .tfbackend.
