Módulo 11

Módulos

Empaquetar y reutilizar infraestructura: crear, versionar y consumir módulos.

🎯 Objetivos de aprendizaje

Al terminar este módulo serás capaz de:

  • Crear un módulo propio con entradas, salidas y documentación.
  • Consumir módulos del Terraform Registry fijando versiones.
  • Diseñar módulos con una responsabilidad clara.

📚 Contenido

  1. Root module vs child modules. Estructura: main.tf, variables.tf, outputs.tf, versions.tf, README.md, examples/.
  2. Bloque module: source, version, entradas, module.nombre.output.
  3. Fuentes: ruta local, Registry público, Git (?ref=v1.2.0), registro privado.
  4. Meta-argumentos en módulos: count, for_each, providers, depends_on.
  5. Módulos populares: terraform-aws-modules/vpc/aws, .../ec2-instance/aws, .../s3-bucket/aws.
  6. Buenas prácticas: no envolver un único recurso, no configurar providers dentro del módulo, versionado semántico, documentar con terraform-docs.
  7. terraform get y terraform init para descargar módulos.
✍️ Lección en desarrollo. Este es el guion del módulo. Ve sustituyendo este aviso por la explicación completa de cada punto.

🧩 Ejemplo

🛠 Práctica guiada: Módulo de web estática

  1. Crea modules/static-site con un bucket S3 configurado como web.
  2. Expón el nombre del bucket y la URL como outputs.
  3. Instáncialo dos veces (dev y prod) con for_each.
  4. Sustituye tu VPC manual por el módulo oficial del Registry.
  5. Genera el README del módulo con terraform-docs markdown table.
💸 Recuerda: si has creado recursos en la nube, ejecuta terraform destroy al terminar.

⌨️ Comandos clave

ComandoQué haceCopiar
terraform get -updateDescarga/actualiza los módulos.
terraform init -upgradeActualiza módulos y providers.
terraform-docs markdown table ./modules/static-siteGenera documentación de inputs/outputs.
terraform state list module.vpcRecursos dentro de un módulo.

⚠️ Errores frecuentes

Module not installed
Has añadido un módulo nuevo: ejecuta terraform init.
Módulos sin versión fija
Fija siempre version (Registry) o ?ref= (Git) para evitar sorpresas.
