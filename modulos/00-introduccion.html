Temario / Módulo 00

Introducción a la Infraestructura como Código

Qué es la Infraestructura como Código y para qué sirven Terraform y Ansible.

Nivel: BásicoDuración: 1 hTest: 6 preguntasRetos: 1Proyecto: paso 1

Objetivos

Al terminar este módulo sabrás:

  • Explicar qué es la Infraestructura como Código (IaC) y qué problemas resuelve.
  • Diferenciar el enfoque declarativo del imperativo.
  • Entender qué hace Terraform, qué hace Ansible y por qué se usan juntos.
  • Conocer el proyecto que construirás a lo largo del curso.
  • Entender el ciclo de vida básico: escribir → planificar → aplicar → destruir.

Lección

El problema: hacerlo todo a mano

Una web necesita varias piezas: servidores, una red, una base de datos, reglas de firewall... Lo habitual al empezar es crearlas a mano, haciendo clic en la web del proveedor de nube (AWS, Azure, Google Cloud).

Hacerlo a mano trae problemas:

  • Es difícil de repetir. Si necesitas una copia exacta para hacer pruebas, tienes que recordar todos los clics.
  • No queda registro. Nadie sabe quién cambió algo ni cuándo.
  • Es fácil equivocarse. Un clic de más y algo deja de funcionar.

La solución: Infraestructura como Código

La Infraestructura como Código (IaC) consiste en describir tus servidores, redes y bases de datos en archivos de texto. Una herramienta lee esos archivos y crea todo por ti.

Ventajas:

  • Puedes repetirlo las veces que quieras y siempre sale igual.
  • Guardas los archivos en Git, así que tienes el historial de todos los cambios.
  • Otra persona puede revisar los cambios antes de aplicarlos.

Terraform es la herramienta de IaC más usada.

Describir el resultado, no los pasos

Terraform es declarativo: tú describes qué quieres tener, no los pasos para conseguirlo. Es como pedir en un restaurante: dices «quiero un café» y no explicas cómo se hace.

Terraform y otras herramientas

Hay otras herramientas parecidas. Esta es la diferencia principal:

HerramientaPara qué sirve
TerraformCrear infraestructura en cualquier nube (AWS, Azure, Google Cloud...) con el mismo lenguaje
OpenTofuUna copia libre de Terraform. Funciona casi igual
CloudFormationLo mismo que Terraform, pero solo para AWS
AnsibleConfigurar lo que hay dentro de los servidores (instalar programas, crear usuarios)

En resumen: Terraform crea las piezas; herramientas como Ansible configuran lo que hay dentro.

Las tres piezas de Terraform

  1. Terraform: el programa que instalas en tu ordenador.
  2. Providers: complementos que saben hablar con cada servicio (uno para AWS, otro para Azure, otro para GitHub...). Se descargan solos.
  3. Estado: un archivo donde Terraform apunta lo que ha creado. Es su memoria.

PasoComandoQué hace
1. Escribir(tu editor)Describes lo que quieres en archivos .tf

Terraform y Ansible: un equipo

En este curso aprenderás dos herramientas que se usan juntas:

HerramientaQué haceEjemplo
TerraformCrea la infraestructuraCrea dos servidores, una red y un firewall en AWS
AnsibleConfigura lo que hay dentro de los servidoresInstala nginx y publica tu web en esos servidores

Piensa en una casa: Terraform construye las paredes, las puertas y la instalación eléctrica; Ansible pone los muebles y lo deja todo listo para vivir.

El proyecto del curso

No solo vas a aprender teoría: a lo largo del curso construirás tu propia web funcionando en AWS. Cada módulo añade una pieza en la sección Proyecto guiado. Al final, un solo comando creará los servidores y los dejará configurados.

Proyecto guiado

Paso 1 de 22: Lo que vas a construir

Al terminar el curso tendrás una web personal funcionando en dos servidores de AWS:

  • Terraform creará una red propia, un firewall, una clave SSH y dos servidores Ubuntu.
  • Ansible instalará nginx en los servidores y publicará tu web, una página de estado y una zona privada con contraseña.
  • Un script lo hará todo con un comando, y otro lo borrará.
  • GitHub Actions revisará cada cambio que subas.

Práctica guiada

Mapa mental de la IaC

  1. Elige una infraestructura sencilla que conozcas (por ejemplo, una web con un servidor y una base de datos).
  2. Escribe los pasos manuales que harías en la consola web para crearla.
  3. Reescribe lo mismo como una lista de «cosas que deben existir» (enfoque declarativo).
  4. Anota qué pasaría si tuvieras que repetirlo en 3 entornos (dev, staging, prod).

Errores frecuentes

Pensar que Terraform sirve para instalar software dentro de servidores
Terraform crea y gestiona recursos; la configuración interna suele hacerla otra herramienta (cloud-init, Ansible, imágenes).
Creer que hay que aprender un lenguaje de programación
HCL es un lenguaje de configuración sencillo; no necesitas saber programar.

01¿Qué describe un archivo de Terraform?

Terraform es declarativo: describes el resultado deseado y él calcula los pasos.

02¿Qué significa que una herramienta sea idempotente?

Si la infraestructura ya está como describe el código, volver a aplicarlo no cambia nada.

03¿Qué pieza de Terraform sabe hablar con la API de AWS?

Los providers son plugins que traducen tus recursos a llamadas a la API de cada servicio.

04¿Cuál de estas tareas es más propia de Ansible que de Terraform?

Configurar el interior de los servidores es gestión de configuración; Terraform se centra en aprovisionar recursos.

05¿Qué es OpenTofu?

Nació en 2023 tras el cambio de licencia de Terraform; usa los mismos archivos y comandos con tofu.

06¿Qué comando enseña los cambios SIN aplicarlos?

plan es una simulación: compara lo que describes con lo que existe y muestra las diferencias.
