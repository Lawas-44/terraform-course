🎯 Objetivos de aprendizaje

Al terminar este módulo serás capaz de:

  • Organizar un repositorio de infraestructura para varios entornos.
  • Automatizar fmt, validate, plan en cada Pull Request.
  • Autenticar GitHub Actions en AWS sin claves (OIDC).
  • Conocer HCP Terraform y alternativas (Atlantis, Spacelift, env0).

📚 Contenido

  1. Estructura de repositorio: modules/, envs/dev, envs/prod, bootstrap/.
  2. Flujo GitOps: rama → PR → plan automático → revisión → merge → apply.
  3. Guardar el plan (-out) y aplicar exactamente ese plan.
  4. GitHub Actions: hashicorp/setup-terraform, caché de plugins, comentarios con el plan.
  5. OIDC: rol IAM de confianza para GitHub, sin secretos de larga duración.
  6. TF_IN_AUTOMATION, -input=false, -no-color, códigos de salida (-detailed-exitcode).
  7. Políticas como código: Sentinel / OPA (visión general).
✍️ Lección en desarrollo. Este es el guion del módulo. Ve sustituyendo este aviso por la explicación completa de cada punto.

🧩 Ejemplo

🛠 Práctica guiada: Pipeline de infraestructura

  1. Reorganiza tus labs en modules/ + envs/dev + envs/prod.
  2. Crea el proveedor OIDC y el rol IAM para GitHub (¡con Terraform!).
  3. Añade el workflow de ejemplo y abre un PR para ver el plan.
  4. Añade un job de apply que solo se ejecute al hacer merge en main.
💸 Recuerda: si has creado recursos en la nube, ejecuta terraform destroy al terminar.

⌨️ Comandos clave

ComandoQué haceCopiar
terraform plan -out=tfplanGuarda el plan en un archivo.
terraform show tfplanMuestra el contenido de un plan guardado.
terraform apply tfplanAplica exactamente el plan guardado.
terraform plan -detailed-exitcodeSale con 0 (sin cambios), 1 (error) o 2 (hay cambios).
terraform -chdir=envs/dev planEjecuta en otra carpeta sin hacer cd.

⚠️ Errores frecuentes

Guardar access keys de AWS como secretos de GitHub
Usa OIDC con un rol de permisos mínimos.
Aplicar desde el portátil y desde CI a la vez
Define una única vía de despliegue y respétala.
