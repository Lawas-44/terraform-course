Organizar un repositorio de infraestructura

Cuando el código crece y hay varios entornos, una estructura clara es fundamental. La más extendida separa módulos reutilizables de configuraciones por entorno:

  • Cada entorno tiene su propio estado: un error en dev nunca toca prod.
  • Las diferencias entre entornos están a la vista en sus tfvars.
  • Para promocionar un cambio: se prueba en envs/dev y después se aplica igual en envs/prod.
ℹ️ Nota. Herramientas como Terragrunt reducen la repetición entre carpetas de entorno. Merece la pena mirarla cuando tengas muchos entornos o cuentas.

Autenticación sin claves: OIDC

Para que GitHub Actions despliegue en AWS lo peor que puedes hacer es guardar access keys como secretos del repositorio (duran para siempre y se filtran). Lo correcto es OIDC: GitHub emite un token temporal en cada ejecución, AWS confía en GitHub y entrega credenciales que caducan en una hora.

Pipeline con GitHub Actions

Este workflow hace plan en cada Pull Request (y lo comenta en el PR) y apply al hacer merge en main:

  1. Guarda el ARN del rol (output role_arn) como secreto AWS_ROLE_ARN en Settings → Secrets and variables → Actions. No es un secreto en sentido estricto, pero así no lo repites.
  2. Abre un PR que cambie algo en envs/dev: verás el plan como comentario.
  3. Haz merge: el job aplica el cambio.
💡 Consejo. Para producción, crea un GitHub Environment llamado prod con required reviewers. Añade environment: prod al job de apply y GitHub pedirá aprobación manual antes de ejecutarlo.

Reglas de convivencia

  • Una sola vía de despliegue: si se aplica desde CI, nadie aplica desde su portátil (permisos de solo lectura para las personas).
  • Cambios pequeños: un PR con un plan de 3 recursos se revisa bien; uno de 300, no.
  • Lee el plan en el PR, no solo el código. Busca especialmente destroy y -/+.
  • Protege la rama main: PR obligatorio, revisiones y checks en verde.
  • Fija versiones: Terraform (required_version, .terraform-version), providers (lock file) y módulos.
  • Documenta: README por entorno y por módulo (terraform-docs).

⌨️ Comandos clave

ComandoQué haceCopiar
terraform plan -out=tfplanGuarda el plan en un archivo.
terraform show tfplanMuestra el contenido de un plan guardado.
terraform apply tfplanAplica exactamente el plan guardado.
terraform plan -detailed-exitcodeSale con 0 (sin cambios), 1 (error) o 2 (hay cambios).
terraform -chdir=envs/dev planEjecuta en otra carpeta sin hacer cd.

Permite solicitar el token OIDC a GitHub.
