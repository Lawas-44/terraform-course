El proyecto

Vas a construir, de principio a fin, la infraestructura de una web escalable en AWS aplicando todo lo aprendido. Es un proyecto ideal para tu portfolio y para preparar la certificación.

⚠️ Cuidado. El Application Load Balancer no es gratuito (unos 0,025 USD/hora + tráfico, ≈ 20 USD/mes). Despliega, prueba y destruye en la misma sesión. Evita el NAT Gateway: en este diseño las instancias van en subredes públicas protegidas por security groups para ahorrar costes.

Módulo web

El entorno dev

¡El balanceador reparte las peticiones entre las dos instancias! Las instancias tardan 2-3 minutos en pasar el health check; hasta entonces verás errores 502/503.

Ideas para subir de nivel

  • Mover las instancias a subredes privadas con NAT Gateway (o VPC endpoints) — es lo correcto en producción, aunque cueste más.
  • Añadir HTTPS con un certificado de ACM y un dominio en Route 53.
  • Una política de autoescalado por CPU (aws_autoscaling_policy con target tracking).
  • Una base de datos RDS en subredes privadas con manage_master_user_password.
  • CloudFront delante del bucket de estáticos.
  • Alarmas de CloudWatch y un dashboard, todo en Terraform.

La certificación Terraform Associate

La certificación HashiCorp Certified: Terraform Associate valida los conocimientos de este curso. Datos orientativos (compruébalos siempre en la web oficial de HashiCorp, porque cambian con cada versión del examen):

  • Formato: online y supervisado, unos 60 minutos, preguntas de opción múltiple, verdadero/falso y respuesta corta.
  • Validez: 2 años.
  • Nivel: el de este curso. No hace falta experiencia profesional previa.

Consejos para el examen:

  1. Repasa la chuleta de comandos del curso hasta saber qué hace cada flag.
  2. Haz los tests de autoevaluación de todos los módulos y repite los que no aprobaste.
  3. Lee los tutoriales oficiales de developer.hashicorp.com/terraform y su guía de estudio.
  4. Practica, practica: escribir código es la mejor preparación. Las preguntas son muy prácticas.

🛠 Práctica guiada: Web escalable en AWS

  1. Dibuja el diagrama de arquitectura antes de escribir código.
  2. Implementa los módulos network, web y static-site.
  3. Despliega dev desde CI y comprueba la URL del balanceador.
  4. Ejecuta infracost y documenta el coste estimado.
  5. Destruye todo y deja constancia en el README.
💸 Recuerda: si has creado recursos en la nube, ejecuta terraform destroy al terminar.

Son de los recursos que más cobran por hora. Revisa la factura al día siguiente.

✅ Test de autoevaluación

Elige una respuesta en cada pregunta. Verás la explicación al momento. Con un 80 % o más, el módulo está superado.

1Simulacro · ¿Qué comando debes ejecutar tras añadir un nuevo provider al código?

Cualquier provider o módulo nuevo requiere init.

2Simulacro · ¿Qué afirmación sobre el estado es FALSA?

sensitive no cifra nada en el estado.

3Simulacro · ¿Qué hace terraform apply -refresh-only?

Sincroniza estado ← realidad, previa confirmación.

4Simulacro · Tienes variable "x" { default = 1 }, TF_VAR_x=2 y x = 3 en terraform.tfvars. ¿Valor de var.x?

terraform.tfvars tiene prioridad sobre las variables de entorno.

5Simulacro · ¿Qué meta-argumento evita recrear recursos al quitar un elemento intermedio de una colección?

for_each identifica cada copia por clave, no por posición.

6Simulacro · ¿Dónde se guardan los providers descargados por init?

El lock file solo guarda versiones y hashes; los binarios van a .terraform/.

7Simulacro · ¿Qué variable de entorno activa los logs detallados de Terraform?

TF_LOG=TRACE|DEBUG|INFO|WARN|ERROR; TF_LOG_PATH para guardarlos.

8Simulacro · ¿Cómo referencias el output vpc_id del módulo network?

module.NOMBRE.OUTPUT.

9Simulacro · ¿Qué bloque permite renombrar un recurso sin destruirlo y queda registrado en el código?

Disponible desde Terraform 1.1.

10Simulacro · ¿Qué es cierto sobre los workspaces CLI?

Mismo código, estados separados; terraform.workspace da el nombre actual.

Responde todas las preguntas para ver tu nota.
