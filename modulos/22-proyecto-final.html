Certificaciones

  • HashiCorp Certified: Terraform Associate: examen online de unos 60 minutos con preguntas tipo test. Este curso cubre su temario.
  • Red Hat Certified Engineer (RHCE): la certificación más conocida de Ansible. Es práctica (resuelves tareas en servidores reales) y más exigente: requiere conocer bien Linux.

Consulta siempre los detalles actualizados en las webs oficiales. Para prepararte, repite los tests de todos los módulos y el simulacro de abajo.

Qué aprender después

  • Linux: cuanto mejor lo conozcas, más fácil te será Ansible.
  • Docker y Kubernetes: Terraform crea los clústeres y hay providers y módulos de Ansible para gestionarlos.
  • Otra nube (Azure o Google Cloud): el flujo de Terraform y Ansible es el mismo; solo cambian los recursos.
  • Terragrunt, OpenTofu y Packer: herramientas del mismo ecosistema.

Proyecto guiado

Paso 22 de 22: Despliegue final y entrega

Último paso: comprueba que todo funciona desde cero, documenta el proyecto y destrúyelo.

  1. Clona tu repositorio en una carpeta nueva y despliega siguiendo solo tu README.
  2. Abre la web en los dos servidores y comprueba que se ve tu nombre y tus proyectos.
  3. Abre /estado.html en cada uno: cada servidor muestra sus propios datos.
  4. Entra en /privado/ con tu usuario y contraseña.
  5. Comprueba que GitHub Actions está en verde.
  6. Haz una captura de la web y añádela al README: es tu proyecto de portfolio.
  7. Destruye todo con ./scripts/destruir.sh.

Práctica guiada

Tu web en la nube, de principio a fin

  1. Clona tu repositorio en una carpeta nueva, como si fueras otra persona.
  2. Sigue solo el README para desplegar todo.

Test

Elige una respuesta en cada pregunta. Verás la explicación al momento. Con un 80 % o más, el módulo está superado.

01Simulacro · ¿Qué comando debes ejecutar tras añadir un nuevo provider al código?

Cualquier provider o módulo nuevo requiere init.

02Simulacro · ¿Qué afirmación sobre el estado es FALSA?

sensitive no cifra nada en el estado.

03Simulacro · ¿Qué hace terraform apply -refresh-only?

Sincroniza estado ← realidad, previa confirmación.

04Simulacro · Tienes variable "x" { default = 1 }, TF_VAR_x=2 y x = 3 en terraform.tfvars. ¿Valor de var.x?

terraform.tfvars tiene prioridad sobre las variables de entorno.

05Simulacro · ¿Qué meta-argumento evita recrear recursos al quitar un elemento intermedio de una colección?

for_each identifica cada copia por clave, no por posición.

06Simulacro · ¿Dónde se guardan los providers descargados por init?

El lock file solo guarda versiones y hashes; los binarios van a .terraform/.

07Simulacro · ¿Qué variable de entorno activa los logs detallados de Terraform?

TF_LOG=TRACE|DEBUG|INFO|WARN|ERROR; TF_LOG_PATH para guardarlos.

08Simulacro · ¿Cómo referencias el output vpc_id del módulo network?

module.NOMBRE.OUTPUT.

09Simulacro · ¿Qué bloque permite renombrar un recurso sin destruirlo y queda registrado en el código?

Disponible desde Terraform 1.1.

10Simulacro · ¿Qué es cierto sobre los workspaces CLI?

Mismo código, estados separados; terraform.workspace da el nombre actual.

11Simulacro · ¿Cómo se conecta Ansible a servidores Linux?

Ansible no necesita agentes: entra por SSH.

12Simulacro · ¿Cuándo se ejecuta un handler de Ansible?

Y se ejecuta una sola vez, al final.

13Simulacro · ¿Qué carpeta de un rol tiene la prioridad de variables más baja?

Por eso es la adecuada para valores que el usuario puede cambiar.

14Simulacro · En el proyecto, ¿quién escribe el inventario de Ansible?

Así las IPs siempre están al día.
