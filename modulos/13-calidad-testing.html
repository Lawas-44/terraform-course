Módulo 13

Validación, testing y seguridad

Condiciones, tests nativos, linters y escáneres de seguridad.

Avanzado⏱ 2,5 h

🎯 Objetivos de aprendizaje

Al terminar este módulo serás capaz de:

  • Añadir precondition, postcondition y bloques check.
  • Escribir tests con terraform test (archivos .tftest.hcl).
  • Integrar TFLint, Trivy/Checkov y pre-commit.
  • Gestionar secretos correctamente.

📚 Contenido

  1. Niveles de validación: validation en variables → precondition/postcondition → check → tests.
  2. terraform test: bloques run, command = plan|apply, assert, mock_provider (1.7+).
  3. Análisis estático: tflint (errores y buenas prácticas del provider).
  4. Seguridad: trivy config (sucesor de tfsec) y checkov.
  5. Automatizar con pre-commit (fmt, validate, tflint, docs).
  6. Secretos: variables de entorno, AWS Secrets Manager/SSM, ephemeral y argumentos write-only en versiones recientes.
  7. Estimar costes con infracost.
✍️ Lección en desarrollo. Este es el guion del módulo. Ve sustituyendo este aviso por la explicación completa de cada punto.

🧩 Ejemplo

🛠 Práctica guiada: Red de seguridad

  1. Añade una postcondition que verifique que la instancia tiene IP pública.
  2. Escribe dos tests con terraform test (uno que pase, uno con expect_failures).
  3. Ejecuta tflint --init && tflint y corrige los avisos.
  4. Pasa trivy config . y arregla al menos un hallazgo.
  5. Configura pre-commit con los hooks de antonbabenko/pre-commit-terraform.
💸 Recuerda: si has creado recursos en la nube, ejecuta terraform destroy al terminar.

⌨️ Comandos clave

ComandoQué haceCopiar
terraform testEjecuta los archivos *.tftest.hcl.
terraform test -filter=tests/bucket.tftest.hcl -verboseEjecuta un test concreto con detalle.
tflint --init && tflint --recursiveDescarga plugins y analiza el código.
trivy config .Escanea configuraciones inseguras.
checkov -d .Escáner de políticas de seguridad.
pre-commit run --all-filesLanza todos los hooks sobre el repositorio.
infracost breakdown --path .Estimación de costes mensuales.

⚠️ Errores frecuentes

Tests con command = apply que crean recursos caros
Usa plan o mock_provider siempre que sea posible.
Ignorar avisos de seguridad sin justificar
Si suprimes una regla, deja un comentario explicando por qué.
