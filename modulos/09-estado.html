Para qué sirve el estado

El archivo terraform.tfstate es la memoria de Terraform. Cumple cuatro funciones:

  1. Mapear código ↔ realidad: sabe que aws_instance.web es la instancia i-0123abcd. Sin esto no podría saber qué recurso real corresponde a cada bloque.
  2. Guardar metadatos: dependencias entre recursos, para poder destruir en el orden correcto aunque ya hayas borrado el código.
  3. Rendimiento: guarda los atributos para no tener que preguntar todo a la API en cada operación (en proyectos grandes, miles de llamadas).
  4. Detectar cambios: comparando estado, código y realidad sabe qué ha cambiado y quién lo cambió.

⚠️ Cuidado. Fíjate en "result": "x7#Kq9!mP2$vL4@n": la contraseña está en texto plano, aunque la marcaras como sensitive. Quien tenga acceso al estado tiene acceso a todos los secretos que gestiona Terraform.

Reglas de oro del estado:

  • Nunca lo edites a mano. Usa los comandos terraform state.
  • Nunca lo subas a Git ni lo compartas por email/chat.
  • En equipo, siempre en un backend remoto cifrado, con versionado y bloqueo (módulo 10).
  • Terraform guarda la versión anterior en terraform.tfstate.backup (solo en estado local).

¿Qué pasa si pierdo el estado?

Si borras terraform.tfstate (y su backup), Terraform «olvida» todo. Los recursos siguen existiendo (¡y cobrando!), pero el siguiente plan querrá crearlos de nuevo, provocando errores de nombre duplicado o recursos repetidos. La solución sería importarlos uno a uno (módulo 12). Por eso el estado se guarda en un backend remoto con versionado.

🛠 Práctica guiada: Provoca y corrige drift

  1. Crea un bucket S3 con etiquetas desde Terraform.
  2. Modifica una etiqueta desde la consola de AWS.
  3. Ejecuta terraform plan -refresh-only e interpreta la salida.
  4. Decide: aceptar el cambio (apply -refresh-only) o revertirlo (apply).
  5. Renombra el recurso en el código y usa terraform state mv para evitar recrearlo.
💸 Recuerda: si has creado recursos en la nube, ejecuta terraform destroy al terminar.

⌨️ Comandos clave

ComandoQué haceCopiar
terraform showMuestra el estado actual de forma legible.
terraform show -json | jqEstado completo en JSON.
terraform plan -refresh-onlyMuestra el drift sin proponer cambios de infraestructura.
terraform state mv aws_s3_bucket.a aws_s3_bucket.bRenombra un recurso en el estado.
terraform state rm aws_s3_bucket.demoDeja de gestionar un recurso (no lo borra).
terraform state pull > backup.tfstateDescarga una copia del estado (incluido remoto).

⚠️ Errores frecuentes

Perder el archivo de estado
Terraform «olvida» los recursos; habrá que importarlos. Por eso se usa backend remoto con versionado.
state rm pensando que borra el recurso
Solo lo quita del estado; el recurso sigue existiendo (y cobrando).
