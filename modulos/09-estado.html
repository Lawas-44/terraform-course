Módulo 09

El estado (state) en profundidad

Qué guarda el estado, el drift y cómo manipularlo sin romper nada.

Nivel: IntermedioDuración: 2 hTest: 6 preguntasRetos: 2Proyecto: paso 10

Objetivos

Al terminar este módulo sabrás:

  • Explicar para qué sirve el estado y qué riesgos tiene.
  • Detectar y corregir el drift (cambios fuera de Terraform).
  • Usar los subcomandos de terraform state de forma segura.

Lección

Qué es el estado

El archivo terraform.tfstate es la memoria de Terraform. Ahí apunta qué ha creado y con qué datos. Por ejemplo, que el recurso aws_instance.web de tu código es el servidor real i-0123abcd de AWS.

Sin ese archivo, Terraform no sabría qué existe ya y querría crearlo todo de nuevo.

Cada vez que ejecutas plan, Terraform compara tres cosas:

  1. Lo que existe de verdad en la nube.
  2. Lo que recuerda (el estado).
  3. Lo que pide tu código.

Con esa comparación decide qué tiene que crear, cambiar o borrar.

Reglas básicas:

  • No edites el estado a mano. Usa los comandos terraform state.
  • No lo subas a Git ni lo envíes por correo.
  • Si trabajas en equipo, guárdalo en un sitio compartido y seguro (módulo 10).

Cambiar el nombre de un recurso

Si cambias el nombre de un recurso en el código (por ejemplo de aws_s3_bucket.viejo a aws_s3_bucket.nuevo), Terraform pensará que es otro recurso: borrará el viejo y creará uno nuevo. Para evitarlo, díselo:

ConsejoEn el módulo 12 verás el bloque moved, que hace lo mismo desde el código.

Olvidar un recurso sin borrarlo

terraform state rm hace que Terraform deje de gestionar un recurso. El recurso no se borra: sigue existiendo en la nube, pero Terraform ya no lo recuerda.

ImportanteSi pierdes el archivo de estado, Terraform olvida todo, pero los recursos siguen existiendo y cobrando. Haz copias o, mejor, guárdalo en un sitio seguro (módulo 10).

Práctica guiada

Provoca y corrige drift

  1. Crea un bucket S3 con etiquetas desde Terraform.
  2. Modifica una etiqueta desde la consola de AWS.
  3. Ejecuta terraform plan -refresh-only e interpreta la salida.
  4. Decide: aceptar el cambio (apply -refresh-only) o revertirlo (apply).
  5. Renombra el recurso en el código y usa terraform state mv para evitar recrearlo.
ImportanteSi has creado recursos en la nube, ejecuta terraform destroy al terminar para no pagar por ellos.

Comandos clave

ComandoQué haceCopiar
terraform showMuestra el estado actual de forma legible.
terraform show -json | jqEstado completo en JSON.

terraform state pull > backup.tfstateDescarga una copia del estado (incluido remoto).

Errores frecuentes

Perder el archivo de estado
Terraform «olvida» los recursos; habrá que importarlos. Por eso se usa backend remoto con versionado.
state rm pensando que borra el recurso
Solo lo quita del estado; el recurso sigue existiendo (y cobrando).
