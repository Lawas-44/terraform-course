Módulo 09

El estado (state) en profundidad

Qué guarda el estado, el drift y cómo manipularlo sin romper nada.

Intermedio⏱ 2 h
En esta página ObjetivosContenidoPrácticaComandosErrores frecuentesAutoevaluación

🎯 Objetivos de aprendizaje

Al terminar este módulo serás capaz de:

  • Explicar para qué sirve el estado y qué riesgos tiene.
  • Detectar y corregir el drift (cambios fuera de Terraform).
  • Usar los subcomandos de terraform state de forma segura.

📚 Contenido

  1. Funciones del estado: mapear código ↔ recursos reales, metadatos, dependencias, rendimiento.
  2. Formato JSON del estado; serial y lineage.
  3. Datos sensibles en el estado: contraseñas, claves… en texto plano.
  4. Drift: terraform plan -refresh-only y terraform apply -refresh-only.
  5. terraform state list | show | mv | rm | pull | push (con precaución).
  6. Copias de seguridad: terraform.tfstate.backup y versionado del backend.
  7. Reglas: nunca editar el estado a mano; nunca compartirlo por email o Git.
✍️ Lección en desarrollo. Este es el guion del módulo. Ve sustituyendo este aviso por la explicación completa de cada punto.

🛠 Práctica guiada: Provoca y corrige drift

  1. Crea un bucket S3 con etiquetas desde Terraform.
  2. Modifica una etiqueta desde la consola de AWS.
  3. Ejecuta terraform plan -refresh-only e interpreta la salida.
  4. Decide: aceptar el cambio (apply -refresh-only) o revertirlo (apply).
  5. Renombra el recurso en el código y usa terraform state mv para evitar recrearlo.
💸 Recuerda: si has creado recursos en la nube, ejecuta terraform destroy al terminar.

⌨️ Comandos clave

ComandoQué haceCopiar
terraform showMuestra el estado actual de forma legible.
terraform show -json | jqEstado completo en JSON.
terraform plan -refresh-onlyMuestra el drift sin proponer cambios de infraestructura.
terraform state mv aws_s3_bucket.a aws_s3_bucket.bRenombra un recurso en el estado.
terraform state rm aws_s3_bucket.demoDeja de gestionar un recurso (no lo borra).
terraform state pull > backup.tfstateDescarga una copia del estado (incluido remoto).

⚠️ Errores frecuentes

Perder el archivo de estado
Terraform «olvida» los recursos; habrá que importarlos. Por eso se usa backend remoto con versionado.
state rm pensando que borra el recurso
Solo lo quita del estado; el recurso sigue existiendo (y cobrando).
